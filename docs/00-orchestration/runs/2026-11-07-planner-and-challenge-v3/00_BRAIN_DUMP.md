## Decisions taken during the run

1. **Drag and drop is live and works in Chromium** (scout ran it; the live bundle carries it). The user's answer: it failed on desktop and on a phone, "I did not know it existed", "on the live application only move up or down is possible". Decision: keep the engine; add a visible handle on every row at every width, a touch drag that starts from the handle with no hold, a mouse drag on coarse-pointer devices, and the Top 3 cap on drop.
2. **Fill from yesterday** copies the Top 3 into today's empty Top 3 slots and the list; done tasks come back unticked; `scheduledAt` is cleared (no event exists for the copy); legacy `manualLoggedMinutes` is dropped; one undoable button as now. This reverses the 2026 "MUSTs are a daily intention" rule on the user's explicit request.
3. **Duration**: the user chose "Both": visible on every row, typed hours and minutes accepted. Parser rules fixed in spec 02 (a bare integer ≥ 10 is minutes; below 10 or with a decimal is hours; the add line only parses a trailing token with a unit or h:mm).
4. **Edit the dates**: creator only, active only; the end may not be before any member's today; the start may not move past the first recorded lock-in or check-in; deadlines editable in the same sheet; rows never deleted.
5. **Goals get ids** like don'ts; legacy string goals normalised on read (`goal-legacy-<i>`); the old client's string args still accepted.
6. **Daily marks** (`markDay`) live on the dashboard's Today surface and in the check-in sheet; a mark is not one of the two daily acts and does not touch inactivity.
7. **Completion rate**: the summary carries planned and done minutes (private tasks included as aggregates); a per-day percentage in `MemberRow`; a season duration-weighted percentage in head to head; the `SeasonGrid` stays as it is.
8. Builders branch from `main` and merge `run/2026-11-05-solo-countdown` first; the backend ships before `main`.
